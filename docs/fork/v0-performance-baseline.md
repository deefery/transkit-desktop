# V0：性能基线

> 路线图任务 V0 · 测量日期：2026-11-25 · 对应提交：`8692154b`（W1 合并后的 `custom/main`）
>
> 后续性能任务（P1 按需加载代码、P2 按需创建窗口）都用同一个脚本重测，与本文对比。

## 1. 结论

| 指标 | 中位数 | 范围（5 次） |
|---|---|---|
| 启动到本地服务可用 | 1594 ms | 1541–1693 ms |
| 启动到 daemon 页面加载完成 | 1619 ms | 1576–1737 ms |
| 空闲内存（私有，进程树合计） | 374 MB | 367–378 MB |
| 空闲内存（工作集，进程树合计） | 630 MB | 621–634 MB |
| 空闲时进程数 | 10 个（其中 WebView2 9 个） | — |
| 首次弹出翻译窗（创建窗口） | 701 ms | 696–775 ms |
| 再次弹出翻译窗（窗口已存在、隐藏） | 112 ms | 94–157 ms（15 次） |
| 弹出过翻译窗后的内存（私有） | 456 MB | — |

要点：

- **空闲时已经有 4 个页面在跑**：daemon、Live Interpreter（monitor）、Voice Anywhere 和它的字幕窗。4 个渲染进程合计约 173 MB 私有内存，是 P2 的主要目标。
- **每个窗口都加载同一个 3.3 MB 的 JS 包**（外加 664 KB CSS），首次弹窗的 700 ms 里有相当一部分是解析和执行这个包。这是 P1 的目标。
- **再次弹出很快（约 110 ms）**，因为翻译窗失焦或按 Esc 后只是隐藏，不会销毁。
- GPU 进程单独占约 130 MB 私有内存，与窗口数量关系不大，P1、P2 都不会明显改变它。

## 2. 空闲内存构成

启动 20 秒后，按 WebView2 进程类型拆分（单次测量）：

| 进程 | 私有内存 | 工作集 |
|---|---|---|
| GPU 进程 | 130.1 MB | 102.9 MB |
| 渲染进程 ×4（4 个预先创建的页面） | 61.7 / 45.8 / 40.7 / 24.7 MB | 100.3 / 83.2 / 77.2 / 50.8 MB |
| WebView2 主进程 | 42.8 MB | 123.0 MB |
| 网络服务 | 11.7 MB | 38.1 MB |
| 应用本身（Rust） | 9.0 MB | 28.0 MB |
| 存储服务 | 7.5 MB | 19.4 MB |
| 崩溃上报 | 2.4 MB | 8.0 MB |

工作集会把共享页重复计算，进程之间相加偏大；**对比时以私有内存为准**。

## 4. 测量方法

脚本：[`scripts/fork/perf-baseline.mjs`](../../scripts/fork/perf-baseline.mjs)，需要 Node 22 和 PowerShell。

```powershell
node scripts/fork/perf-baseline.mjs --exe <transkit.exe 路径> --identifier <构建时的 bundle identifier> --runs 5 --out result.json
```

**被测构建**：release 构建，前端嵌入（`cargo build --release --features custom-protocol`），通过环境变量 `TAURI_CONFIG` 换成单独的 bundle identifier，使用 `%APPDATA%` 下独立的配置目录，不碰已安装的 TransKit 及其设置。脚本首次运行时给这个配置写入：独立的本地服务端口、不检查更新、不监听剪贴板、翻译窗失焦不自动关闭（由脚本用 Esc 隐藏）。其余都是默认配置（包括默认开启的 Voice Anywhere）。

**每一轮**都重新启动应用：

1. **启动**：从创建进程开始计时，到本地 HTTP 服务能连上；再到 daemon 页面 `document.readyState === 'complete'`。
2. **空闲内存**：启动 20 秒后，统计应用进程及其所有子进程（即全部 WebView2 进程）的私有内存（`PrivatePageCount`）和工作集。
3. **首次弹窗**：向本地服务 POST 一句话（与划词翻译走同一个窗口），到翻译窗页面已经接收并渲染了这句话（源文本框里是这句话，划词面板已经显示）。Rust 端会在页面加载前就把窗口显示出来，所以"窗口可见"不能代表用户看到内容，这里以页面渲染完成为准。**翻译结果本身取决于翻译服务的网络往返，不计入。**
4. **再次弹窗**：按 Esc（划词面板自己的 Esc 逻辑会隐藏窗口），再 POST 另一句话，同样计到渲染完成。每轮 3 次。
5. 弹窗后的内存再测一次，然后结束进程树。

页面状态通过 WebView2 远程调试端口读取（只监听本机）。打开调试端口本身会带来很小的额外开销，前后对比都在同样条件下进行，因此可以忽略。

## 6. 限制

- 只有一台机器、5 轮，每轮之间系统缓存是热的；**开机后第一次启动（冷启动）没有测**。
- "首次弹窗"是应用已经运行时第一次创建翻译窗，不包括启动过程。
- 测的是本地服务触发的弹窗；划词快捷键还要加上读取选中文字的时间（UI Automation 或模拟复制），这部分与本文的优化无关。
- 内存会随使用增长（例如打开过设置窗、Live Interpreter），本文只覆盖"刚启动"和"弹出过翻译窗"两个状态。

## 7. 对后续任务的意义

- **P1（按需加载代码）**：重测"首次弹窗"和各窗口渲染进程的内存，并对比第 3 节的 JS 包大小。目标是翻译窗的首屏 JS 明显小于 3.3 MB、首次弹窗明显快于 700 ms。
- **P2（按需创建窗口）**：重测"空闲内存"和进程数。Live Interpreter 不预先创建，最多可少 1 个渲染进程；Voice Anywhere 默认开启自启动，需要决定开启时是否仍然启动即创建，否则这部分节省只对关闭自启动的用户生效。
